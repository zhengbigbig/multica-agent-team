# Multica 数字员工团队 v2

一套真实在用的 3 人「数字员工」团队终态配置：在 [Multica](https://github.com/multica-ai/multica)（开源的人 + AI 编码 agent 混合团队工作区）上自托管，**Codex CLI 作为运行时，全员 gpt-6-sol（high 推理档）**。

在一个真实线上缺陷单上完整跑通：一句话需求接单 → 并行定位挖出四层叠加根因 → QA 独立验证打回 → 当天修复闭环，全程按角色留痕、成本按卡归因。

## 编制（3 人）

| Agent | 模型 | 推理档 | 职责 | 内置规矩 |
| --- | --- | --- | --- | --- |
| 队长 | gpt-6-sol | high | 分诊（先翻历史禁盲改）、执行 spec、排程派单、集成协调、汇总终审包 | 终审代理规则、推送确认规则、确认话术 |
| 全栈开发 | gpt-6-sol | high | 前后端全栈交付 | 完成与确认推送（分支@SHA + 测试位置 + 白话结论） |
| QA | gpt-6-sol | high | 独立验收：五步流水线 + 截图证据 + 打回 | 证据与范围纪律（绑症状、对照实验、报告话术） |

运行时为 [Codex CLI](https://github.com/openai/codex)（OpenAI 兼容网关接入），换成 Claude Code / Cursor 等 CLI 配置不变。

## 内置规矩（全部硬编码进指令，写文档没用）

- **终审代理规则**：子任务验收报告齐备即由代理放行；入口任务终审只核 QA 验证截图与报告结论
- **完成与确认推送**：交付必贴分支@SHA + 测试位置 + 一两句白话结论；需用户拍板时卡挪 blocked 等一句回复
- **确认话术 / 报告话术**：凡需确认或报告，一两句白话，禁止长篇技术叙述
- **证据与范围纪律**：验收范围绑症状不绑改动面；模型回答必须经对照实验证实；截图必须是本单修复的直接证据
- **分支纪律**：没有人类确认标记，禁止推主干

## 目录

```
agents/          3 个 agent 的岗位指令（原样可复制）
agents.json      机器可读全量配置
skills/          项目「代码地图」skill 示例（仓库索引/路由树/域锚点/部署链路排查法）
```

## 建队步骤

1. 自托管 Multica（三容器）并 `multica setup self-host` 登录，daemon 常驻
2. 安装 Codex CLI 并配置网关，daemon 自动探测注册为运行时
3. 按 `agents/*.md` 逐个创建 agent：模型、推理档、指令原样填入
4. 把 `skills/` 的代码地图结构套到你自己的项目上，创建为工作区 skill，全员绑定

## 两条经验

1. **缺陷单先定位再动手**：实现者自测全绿 ≠ 能用，UI 级缺陷只有独立验收才抓得到
2. **确认要白话**：需要人拍板时一两句话说清"做什么、等什么答复"，长文没人看
