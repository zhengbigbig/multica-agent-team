# Multica 数字员工团队模板

一份真实在用的 8 人「数字员工」团队配置：在 [Multica](https://github.com/multica-ai/multica)（开源的人 + AI 编码 agent 混合团队工作区）上自托管后，按本仓库的配置即可复制这套团队。

背景实录见公众号文章《Multica 全干流水线实录：真实项目、8 个 Agent、一次真实事故》——团队在一张真实线上缺陷单上：一句话需求接单、并行定位挖出四层叠加根因、当天修复闭环。

## 编制

| Agent | 模型 | 职责 |
| --- | --- | --- |
| 队长 | glm-5.3 | 分诊、派单、汇总、转人工（工作区 Owner） |
| spec 工程师 | glm-5.3 | 复杂任务的调研与执行 spec |
| FE-小程序 | glm-5.3-flash | 小程序全部页面 |
| BE-小程序 | glm-5.3-flash | 小程序主链路 + 记账 + 3D 空间接口 |
| FE/BE-运维后台 | glm-5.3-flash | 运维面板前后端 |
| QA | glm-5.3-flash | 独立验收：五步流水线 + 截图证据 |
| 运维 | glm-5.3-flash | 小程序发版 + 后台部署 |

## 目录

```
agents/          8 个 agent 的岗位指令（instructions）逐人一份
agents.json      机器可读全量配置
skills/          绑定给全员的项目「代码地图」skill 示例
```

## 建队步骤

1. 自托管 Multica（三容器）并用 CLI 登录
2. 按 `agents/*.md` 逐个创建 agent：模型、描述、指令原样填入
3. 把 `skills/` 里的代码地图按你自己的项目改写（仓库索引 / 路由树 / 域锚点 / 部署链路），创建为工作区 skill
4. 在队长与各域 agent 的指令里开头加一句：先读代码地图再干活

## 三条配置经验（踩坑换来的）

1. **判断用贵模型，执行用便宜模型**——队长 / spec 用旗舰档，干活的用 flash 档
2. **验收必须换模型**——与实现者错开盲区
3. **规矩写进指令**——分支纪律、发版人类确认、验收绑症状，全部硬编码进岗位指令，写在文档里没用

## 本仓库的真实项目背景

- 项目：记账 + 物品管理小程序（uni-app 前端 + Django 后端，在营产品）
- 用法示例：把 `skills/home-assistant-代码地图.md` 的结构套到你自己的仓库上
